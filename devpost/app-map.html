Ask Groq for structured notes

The server sends chapter text and the optional focus. A strict schema checks each chapter's title, main points, formulas, and theorems before the result returns.

Render and download

React renders the chapter sections. The browser builds a named Markdown or plain-text file and downloads it locally; the server doesn't store a copy.

How the deployed app runs

During development, Vite serves the React client and proxies API calls to Express. In production, Express serves the built client and API from one origin. Render supplies the port; the Groq key remains a server environment secret.

A practice to reuse

Add a fourth study section, Definitions, end to end. This practices the same vertical-slice pattern used for PDF input and both export formats.

  1. Add a definitions string array to both the Zod schema and provider JSON schema in summary.js; update the model instructions in groqSummarizer.js.
  2. Render the new section in SummaryResults.jsx.
  3. Include it in both output formats in markdown.js.
  4. Extend schema, rendering/export, and API tests; run npm test and npm run build.

Keep one consistent field name across the provider schema, UI, both exporters, and tests. That consistency is what lets the data travel through the whole app.
